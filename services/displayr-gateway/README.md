## Pending integration

- Apply the reviewed optional setup SQL in `../../docs/portal_displayr_gateway.sql` to the selected pilot environment, then verify the real callback. The implemented callback validates the supplied access token with Supabase Auth and calls a service-role-only RPC checking its active `auth.sessions` row, current user/workspace/subscription/dashboard entitlement and an active visible mapping. It uses no mock-data fallback. The private security-definer helper is necessary because the real service role has no SELECT privilege on `auth.sessions` or `auth.users`; the exposed wrapper is security invoker. No broad Auth table grants are added.
- Callback input: `{accessToken, companyId, dashboardSlug}`. Authorized output: `{userId, expiresAt, dashboardPath, documentIds}`; expiry is Unix milliseconds bounded by the verified portal token. Deny all other requests. Identity and dashboard routing must come from authoritative records.
- Configure the disabled-by-default pilot flag and isolated gateway origin. The portal frame policy includes the validated gateway origin only when enabled. Never expose the private control listener, control secret, access token or Displayr cookie jar to browser code.
- Local tests cover broker single-flight/cache expiry/failure cooldown, cookie copy isolation, callback revocation/expiry, external dashboard decisions, control authorization and opaque ticket launch. More coverage is needed for login adapter errors and real portal identity isolation.
- Automatic Displayr sign-in passed using the actual `login.mjs` adapter, with credentials supplied via non-echoing stdin and no credential/cookie files or authenticated browser left behind. Cached broker sessions expire after ten minutes, but active gateway sessions do not yet renew upstream authentication. Never automatically replay saves or export POSTs.
- Verify two separate real viewers, logout, full Explore and exports end to end before deployment. Prior successful private transport tests are documented in `../../experiments/displayr-gateway/PRIVATE-RESULTS.md`; they used separately seeded cookies and do not prove this new integration.
